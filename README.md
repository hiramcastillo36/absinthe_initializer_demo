# AbsintheInitializer Demo

Demo Phoenix 1.8 API showcasing every configuration mode of [`absinthe_initializer`](https://github.com/hiramcastillo36/absinthe_initializer) — one branch per feature combination, ready to run with Docker Compose.

## Branches (Feature Showcase)

Switch branches to inspect the exact files generated by each CLI combination:

| Branch | Command Used | Transport | Cache | Rate Limit | Best For |
| --- | --- | --- | --- | --- | --- |
| **`main`** *(this branch)* | `mix absinthe_initializer --auth` | `:both` (HttpOnly Cookie + Bearer) | `:ets` (0 deps) | Enabled (ETS) | Most Phoenix + GraphQL apps (Web + Mobile) |
| **`basic-no-auth`** | `mix absinthe_initializer` | None | None | None | Simple GraphQL API without user accounts |
| **`auth-cookie-only`** | `mix absinthe_initializer --auth --auth-transport cookie --cache ets` | `:cookie` (HttpOnly, hides token in JSON) | `:ets` | Enabled (ETS) | Browser SPAs (React, Vue, Next.js) |
| **`auth-bearer-cachex`** | `mix absinthe_initializer --auth --auth-transport bearer --cache cachex` | `:bearer` (`Authorization` header) | `:cachex` | Enabled (ETS) | Mobile / API clients using Cachex |
| **`auth-minimal`** | `mix absinthe_initializer --auth --auth-transport bearer --cache none --no-rate-limit` | `:bearer` | `:none` (direct DB) | Disabled | Minimal auth without ETS GenServers |

## Quick Start (Docker Compose)

```bash
docker compose up --build
```

- **GraphQL API:** `http://localhost:4000/api`
- **GraphiQL IDE (dev only):** `http://localhost:4000/graphiql`

## Run Tests

```bash
docker compose run --rm app sh -c "MIX_ENV=test mix ecto.create && MIX_ENV=test mix ecto.migrate && MIX_ENV=test mix test"
```

## Example GraphQL Requests (`main` — Cookies + Bearer + ETS Cache + Rate Limit)

### 1. Sign Up (stores SHA-256 token hash in DB, sets `HttpOnly` cookie, returns token)

```bash
curl -i -c cookies.txt -X POST http://localhost:4000/api \
  -H "Content-Type: application/json" \
  -d '{
    "query": "mutation SignUp($email: String!, $password: String!) { signUp(email: $email, password: $password) { token user { id email isAdmin } } }",
    "variables": {"email": "alice@example.com", "password": "super_secure_password_123"}
  }'
```

### 2. Query `me` using the `HttpOnly` Cookie

```bash
curl -b cookies.txt -X POST http://localhost:4000/api \
  -H "Content-Type: application/json" \
  -d '{"query": "query { me { id email isAdmin } }"}'
```

### 3. Query `me` using `Authorization: Bearer`

```bash
curl -X POST http://localhost:4000/api \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <TOKEN>" \
  -d '{"query": "query { me { id email isAdmin } }"}'
```

### 4. Sign Out (or Sign Out All Devices)

```bash
curl -i -b cookies.txt -X POST http://localhost:4000/api \
  -H "Content-Type: application/json" \
  -d '{"query": "mutation { signOut { message } }"}'
```
